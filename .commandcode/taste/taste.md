# Taste
See [taste/taste.md](taste/taste.md)

## Workflow
- Prefers to delegate console/ops tasks to the agent via CLI/API instead of clicking through web consoles manually; when a service has no CLI, is interested in API + service-account automation (e.g. Google Play Developer API, GitLab tokens) so the agent or CI can do it. Confidence: 0.75
- Proposes concrete integration/automation routes himself and expects a feasibility verdict, not research delegation: e.g. "gitlab actions (se tiver algo assim)", "tu não consegue mexer no meu playconsole via cli?", "tem como testar usando isso? <link do GitHub>". Wants a direct what-works / what's-blocked-and-why answer plus the best practical alternative, checked against his actual environment. Confidence: 0.55
- Wants to be able to run and try the app himself before shipping — after a build lands he asks how to test it (external UI-automation tooling, device/emulator), so offer a concrete install/try path (e.g. `adb install` of the debug APK, physical device) rather than only handing over the store bundle. Confidence: 0.55
- Has a physical Android phone for testing and, when he asks "como eu configuro X" (e.g. ws-scrcpy), expects the agent to install/compile/wire the tooling on his machine itself and only tell him the one manual step on the device (USB debugging, accept prompt) — not a tutorial to follow. Once he's done that step he reports it in a few terse words ("conectado via usb em depure") and expects the agent to immediately detect the device and carry on to a working end-to-end result, not to reconfirm or hand back instructions. Confidence: 0.65
- Wants a live-development loop, not edit-then-rebuild: asks "da pra editarmos em tempo real assim?" and expects the agent to switch to the debug build + dev server (Metro/Expo, adb reverse, ws-scrcpy) so every edit lands on the phone within seconds while he watches — set it up proactively and leave it running, plus a screenshot of the result after changes. Confidence: 0.7
- Impatient with slow, blocking external processes (approvals, resets, multi-day verifications): asks whether a mandatory step can be skipped or worked around ("é necessário mesmo resetar? ... não tem como seguir assim?") rather than waiting, and will go hunting for old credentials/artifacts himself to avoid it. Answer honestly whether it's required, then exhaust the cheap recovery paths (git history, leftover files, downloads) before proposing the slow process. Confidence: 0.7
