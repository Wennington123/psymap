# Design

- Prefers minimalist, visually clean UIs — explicitly dislikes "over-CSS" looks with hard borders; favors subtle shadows, more whitespace, clear typographic hierarchy. Judges a screen by whether it still reads as raw "HTML + CSS" / "chapado" (flat, div-on-div, no depth): treats that as a defect to fix with real tonal depth (darker bg vs lighter surfaces), hairline borders/shadows, micro-labels + stronger type scale, and organic shapes over plain squares. Confidence: 0.85
- Likes gamification elements in products (XP, streaks, leaderboards, badges). Confidence: 0.7
- Wants an explicitly "friendly" (amigável) visual identity: rounded corners everywhere (larger radii on cards/inputs/pills), rounded/soft typefaces (welcomed Nunito over the system font), a consistent set of cute 3D emojis instead of mixed system emojis, and modern line icons. Treat hard edges, square tiles and mixed emoji styles as things to soften. Confidence: 0.7
- Prefers themes built on well-known FOSS palettes (Dracula, Nord, Gruvbox, Catppuccin, plus a plain Dark) over bespoke/invented ones ("sunset", "ocean", "forest", "kittens") — recognizable community palettes give the app real identity. When a customization set feels weak, he'd rather delete the existing options and rebuild a curated list than keep patching them. Confidence: 0.7
- Default theme should be the light one, not dark/Dracula — light-on-demand dark themes rather than dark by default. Confidence: 0.6
- Expects each theme to have a real visual identity beyond swapped colors: asked for a "pixelado" style (pixel font, solid 2px borders, square corners, flat emoji pack) while the modern themes keep rounded corners and soft 3D emoji — i.e. centralize per-theme typography/radius/asset decisions in shared tokens so every screen inherits them. Keeps theme mechanics (badge unlocks, etc.) in the code even when unlocking everything for testing. Confidence: 0.6
- Labels must survive any font/theme without wrapping or truncation — on the pixel theme he noticed "Expectativa" breaking to two lines; typography should auto-fit/scale rather than wrap on short chip labels. Confidence: 0.5
- Prefers a small, canonical set of built-in options over user-extensible customization: cut the custom-emotion flow entirely so the app works only with the 8 base emotions (Plutchik), letting a free-text "Descrição" absorb the nuance — justified by domain/theoretical soundness ("faz mais sentido psicológico") rather than feature count. When a taxonomy risks becoming infinite, he'd rather remove it and deepen the description field than keep adding options. Confidence: 0.6
- Prefers achievement-gated unlocks over paywalls: asked to remove paid themes (premium/priceBRL/sku/sku purchase flow) in Psymap and unlock themes via gamification goals/badges instead — favors frictionless, free user experience for features like customization. Confidence: 0.7
